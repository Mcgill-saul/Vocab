# Grain — 项目说明

这个文档是写给"未来的你"和"未来的我"看的——过一阵子回来看代码，靠这份文档就能快速想起来"这是啥、做到哪了、接下来干嘛"，不用重新读一遍所有代码。

以后对话里直接说 **Grain** 指的就是这个项目。

---

## 这是个什么东西？

一个只有 3 个文件（`Grain.html`、`manifest.json`、`sw.js`）的网页版背单词工具，叫 **Grain**，专门给手机用。它能做到"添加到手机主屏幕"，图标、启动方式都跟真正的 App 一样，断网也能打开——这种技术叫 **PWA**（Progressive Web App），说白了就是"一个网页，但是骗过手机让它表现得像个 App"。

- `Grain.html` —— App 的全部内容（界面 + 逻辑），你平时改功能主要就改这一个文件
- `manifest.json` —— 告诉手机"添加到主屏幕"之后，图标长什么样、App 叫什么名字、打开时是全屏还是带浏览器边框
- `sw.js`（Service Worker）—— 负责离线缓存，让断网的时候也能把 App 打开

## 数据存在哪？会不会丢？

存在**手机浏览器自己的储物柜里**，专业名字叫 `localStorage`。你不用去理解它怎么实现的，只要记住两件事：

1. 它只存在**这一个浏览器、这一台设备**上，换个手机、换个浏览器，数据不会跟过去——但这个短板已经有了两道保险：一是右上角 ⚙ 里的 JSON 导出/导入，可以手动备份；二是 GitHub Gist 云同步，配置好之后改动会自动同步到云端，换设备也能接上（配置方法见后面"云同步怎么配置"）
2. 如果你手动清了浏览器缓存/数据，且既没导出过备份、也没配置云同步，这些单词才会真的丢——正常用的话按上面这两道保险，数据不会说没就没

## 代码是怎么组织的？（命名空间）

打开 `Grain.html` 找 `<script>` 标签，你会看到几乎所有代码都写在一个叫 `App` 的大对象里面，像这样：

```js
const App = {
  config: { ... },   // 写死的配置，比如存储用的 key 叫什么名字、间隔重复的天数表
  state:  { ... },   // 会变化的数据，比如现在有哪些单词、当前在哪个页面
  dom:    { ... },   // 缓存起来的 DOM 节点引用，App.init() 里统一 getElementById 一次
  storage:{ ... },   // 负责存/取 localStorage，也是数据迁移代码写的地方
  utils:  { ... },   // 一些小工具，比如生成随机 id、防止 XSS 的转义函数、图标 SVG
  render: { ... },   // 负责把数据画到屏幕上（词库列表、复习卡片都在这）
  list:   { ... },   // 词库列表相关的状态和交互：左滑手势、释义遮盖/点开、释义总开关
  filter: { ... },   // 场景筛选（按 tag/scene/domain 筛词库列表）
  review: { ... },   // 复习：间隔重复调度（Leitner 盒子算法）
  backup: { ... },   // JSON 导出/导入
  gist:   { ... },   // GitHub Gist 云同步
  sheet:  { ... },   // 负责"添加/编辑单词"那个从底部弹出的表单
  init(){ ... }       // App 启动时第一个执行的函数
};
```

**为什么要这样写**：如果不这样，代码里到处都是散养的变量和函数（比如直接写 `let words = []`、`function save(){}`），项目做大了很容易出现"两个地方不小心用了同一个名字，互相覆盖，出了 bug 也不报错，你自己都不知道哪里出了问题"。套进 `App` 这一个对象里，就不会有这个问题，而且看名字就知道"这是负责存储的""这是负责画面的"，找代码更快。

**以后加新功能的规矩**：
- 如果是一个新的独立功能（比如以后要加"复习"），就在 `App` 下面新开一块，叫 `App.review = { ... }`，不要把代码硬塞进已经有的分组里
- 如果是给已有功能加点东西（比如给"添加单词"表单加个字段），就在对应的分组里加，比如 `App.sheet.save()` 里加一行
- 不要在 `<script>` 标签最外层直接写 `let xxx = ...` 或者 `function xxx(){}`，全部走 `App.xxx.yyy` 这条路径

## 每个单词存的是什么？

```js
{
  id: "w_1234567890_ab12cd",   // 自动生成的唯一编号，你不用管
  word: "abandon",              // 单词本身
  meaning: "放弃，抛弃",         // 中文释义
  example: "He abandoned the car.",   // 英文例句
  exampleZh: "他抛弃了那辆车。",       // 例句的中文翻译
  phonetic: "/əˈbændən/",       // 音标
  pos: "v.",                    // 词性
  tag: "",                      // 标签，你自己定义分类用的（比如身体部位"手臂"这种细分维度）
  scene: "",                    // 场景（比如"gym"、"面试"）
  domain: "",                   // 领域（比如"商务"、"科技"）
  // tag/scene/domain 这三个字段现在是词库页顶部"场景筛选"功能用的筛选条件，不是纯摆设的分类元数据了。
  // 三者语义不同、不强制填全；筛选逻辑是精确匹配（不是模糊搜索），组内多选是"或"，
  // 三个字段之间是"且"。具体交互见下面"现在做到哪一步了"里的"场景筛选"这条
  related: "",                  // 关联词，比如同义词/反义词
  status: 1,                    // 1 = 学习中，2 = 已掌握（手动标记；标成已掌握的词会直接跳出复习队列，不再被抽考，除非手动切回学习中——这点跟下面的间隔重复字段是有联动的，不是完全独立的两回事了）
  date: "2026-09-10",           // 录入日期
  box: 0,                       // 间隔重复用的"盒子等级"，越高代表你记得越熟
  nextReview: 1757123456789,    // 下次该复习这个词的时间戳，复习功能会用到这个字段
  createdAt: 1757123456789      // 创建时间，列表按这个排序（新的在前面）
}
```

`box`/`nextReview` 这两个字段是间隔重复复习功能在用的调度数据，添加单词的时候就会初始化好。

**同一个单词的不同词性/释义，是分开存成多条记录的，不是塞进一条里。** 比如 `book` 当名词"书"和当动词"预订"，会是两条 `word` 都是 "book" 的独立记录，各自有自己的 `id`、`box`、`nextReview`。这么做是因为间隔重复的颗粒度应该是"一个记忆点"，不是"一个单词"——两个义项的熟悉程度可能完全不一样，合并成一条的话复习时没法分别判断"哪个记住了哪个没记住"。列表里也是完全独立的两张卡片显示，不做任何"这俩有关系"的视觉提示——数据本来就是两个独立的东西，界面上没必要硬凑。

## 以后加字段/加功能的注意事项

**如果要给单词加一个新字段**（比如以后想加"词根"）：老单词的数据里是没有这个字段的，直接用会报 `undefined`。做法是在 `App.storage.load()` 里加一段"迁移"代码——检查每个单词有没有这个字段，没有就给个默认值，然后存回去。这个手法已经在 Words.html 那个老项目上验证过一次了（给 209 条老数据补 `box`/`nextReview`），效果稳定，以后照着抄就行。

**每加一块新功能，记得写完就测一遍**——不用多复杂，能验证"加了新东西之后，原来能用的东西还能用"就够了。

## 现在做到哪一步了？

- ✅ 数据结构 + 本地存储
- ✅ 添加/编辑/删除单词（右下角 "+" 按钮，从底部弹出表单）
- ✅ 底部导航栏（Words / Review 两个 tab，SVG 线框图标）
- ✅ PWA 基础设施（manifest、离线缓存、内置图标）
- ✅ **复习功能**（间隔重复算法、今日复习/全部单词切换、翻卡交互）
- ✅ **备份/恢复**（右上角 ⚙ 按钮，JSON 导出 + 导入，导入时会先显示"新增/重复/跳过"数量，选"合并"还是"覆盖"）
- ✅ **云同步**（GitHub Gist，跟 Words.html 共用 Token、但各自独立的 Gist；改动后 8 秒自动推送，推送前会检查云端有没有被其他设备改过，有冲突会弹提示条，不会静默覆盖。**启动时的拉取逻辑后来改过一次**：原来是不管三七二十一直接拉云端覆盖本地，发现这样如果本地刚编辑完、还没等到 8 秒防抖窗口就把页面关了/刷新了，这次编辑会被静默冲掉——现在加了个 localStorage 标记，本地一存档就打标记、推送成功才撕掉；启动时先看这个标记还在不在，还在就说明上次可能有改动没推上去，先尝试推送（自带冲突检测），标记不在才直接拉取）
- ⬜ CSV 导出（备份优先级更高、已经做完，CSV 只是"能被 Excel 打开"的便利格式，不急）
- ✅ **左滑切换状态 + 释义遮盖**（从 Words.html 移植 + 新设计：词库列表卡片左滑在"学习中/已掌握"间切换，方向感知的颜色反馈。释义遮盖后来从"只有已掌握的词才盖"扩展成了一个**总开关**：header 右上角有个眼睛图标，开着的话学习中的词也会跟已掌握的词一样默认盖住释义、点一下看一眼、再点盖回去，把整个词库都能当被动回忆测验用，不用非得先标成已掌握。开关不管开/关都会清空"点开过"的记录，相当于重新开始一轮自测。**已掌握现在会真正跳出复习队列**——之前"已掌握"只是个标签，完全不影响复习调度，标了也照样被抽到考，后来发现这样标记没有意义，改成标了已掌握的词直接不进 Due Today / All Words 的候选池，除非手动切回 Learning）
- ✅ **场景筛选**（App.filter 模块）：词库页 header 有个三横线图标，点开会展开一行三个筛选输入框——Context / Domain / Tag（按常用程度排序），对应单词的 scene/domain/tag 三个字段。三个都是能直接打字的真输入框（点一下就弹键盘），打字会弹出建议卡片、按已有数据做子串过滤，必须点建议项才算选中（不能直接把打的字当筛选值，避免打错字筛出空列表却不知道为什么）；选中的值变成可删除的 chip。筛选逻辑：同一个字段选多个值是"或"，三个字段之间是"且"，且是精确匹配、不是模糊搜索。这套筛选目前只作用于"浏览词库列表"，不影响复习抽词。默认收起，减少 header 常驻的视觉占用；有筛选生效时图标会变强调色提示
- ✅ **列表展示优化**：单词行是"单词 + 词性 + 释义 + 状态"同一行显示，释义太长会省略号截断（换来单词不用单独占一行）。同一个单词的多个词性/释义（比如 book 的 n. 和 v.）**每条都是完全独立的卡片，不做分组**——试过做成"共享一个标题"的分组样式，讨论下来觉得没必要：既然复习进度、编辑入口都是各自独立的，视觉上硬凑一个"这俩有关系"的提示反而是画蛇添足
- ✅ **搜索**：词库页顶部加了放大镜图标 + 搜索框（英文 placeholder "Search"，浅灰色），按单词和释义文本匹配，输入的时候只重画结果列表、不重建搜索框本身，不会因为重新渲染而丢失输入焦点
- ✅ **Part of Speech 历史值建议**：添加/编辑单词表单里，词性这个字段打字会弹出建议卡片（跟场景筛选的建议卡片同一套视觉，但是单选，点了直接填入输入框），从已有词库里收集用过的词性值，不用每次手打
- ✅ 添加单词表单的输入框去掉了占位提示文字，都是空白；"More"折叠区（音标/词性/标签等次要字段）统一保持默认收起，不管里面有没有数据
- ✅ **顶部/底部固定定位修了一轮 bug**：底部导航栏和"+"添加按钮之前会随着单词卡片增多一直往下掉（`#app` 没有固定高度、这两个元素之前错误地用 `position:absolute` 贴着 `#app` 底部而不是真正贴屏幕底部），已改回 `position:fixed`；顶部 header 和筛选行之前也是随列表内容滚走的，现在用 `position:sticky` 贴住顶部。顺带修了两个只有桌面浏览器预览时才会看到、手机上没有影响的小问题：宽窗口下"+"按钮会飘到居中窄栏外面的空白区域（加了个跟导航栏同款的居中容器）、切换词库/复习 tab 时 header 会左右跳动（页面级的滚动条出现/消失导致布局宽度变化，加了 `scrollbar-gutter:stable` 让滚动条永远占位）
- ⬜ 批量操作

## 云同步怎么配置

1. GitHub 网页右上角头像 → Settings → Developer settings → Personal access tokens → 生成一个新 token，权限勾 `gist` 就够了（Words.html 那边如果还在用，同一个 token 可以直接复用）
2. App 里点右上角 ⚙ → 云同步，把 Token 填进去，**Gist ID 留空**，点保存——会自动新建一个私有 Gist 并把 ID 填回来，不用自己去 gist.github.com 手动建
3. 如果你想手动指定一个已有的 Gist（比如换设备后想接到同一个），把它的 ID 填进去再保存就行，**注意不要跟 Words.html 用的是同一个 Gist**，复用同一个会导致两边互相误报"云端冲突"，这个在前面的讨论里踩过一次坑

配置完之后，改动会在停止编辑 8 秒后自动同步，不用每次手动点。

## 部署方式

跟之前 `vocab-pwa` 项目一模一样：新建一个干净的 GitHub 仓库，把 `Grain.html`、`manifest.json`、`sw.js` 这 3 个文件传到根目录（`README.md` 这份文档不影响运行，但建议一起传上去，方便以后翻）。传完 Settings → Pages 里开启，等生成网址后手机浏览器打开、添加到主屏幕。**不要传进 Words.html 正在用的那个仓库**——现在功能还没搬齐，传进去会把正在用的工具替换成半成品。

**注意**：主文件叫 `Grain.html` 不是 `index.html`，所以网址不是干净的 `你的用户名.github.io/repo/`，得完整打上文件名：`你的用户名.github.io/repo/Grain.html`。只有第一次部署时需要记这个完整网址——"添加到主屏幕"之后，图标记的就是这个完整地址，以后点图标直接打开，不用再手动输。
