# Grain — 项目说明

这个文档是写给"未来的你"和"未来的我"看的——过一阵子回来看代码，靠这份文档就能快速想起来"这是啥、做到哪了、接下来干嘛"，不用重新读一遍所有代码。

以后对话里直接说 **Grain** 指的就是这个项目。

---

## 这是个什么东西？

一个只有 3 个文件（`Grain.html`、`manifest.json`、`sw.js`）的网页版背单词工具，叫 **Grain**，专门给手机用。它能做到"添加到手机主屏幕"，图标、启动方式都跟真正的 App 一样，断网也能打开——这种技术叫 **PWA**（Progressive Web App），说白了就是"一个网页，但是骗过手机让它表现得像个 App"。

- `Grain.html` —— App 的全部内容（界面 + 逻辑），你平时改功能主要就改这一个文件
- `manifest.json` —— 告诉手机"添加到主屏幕"之后，图标长什么样、App 叫什么名字、打开时是全屏还是带浏览器边框
- `sw.js`（Service Worker）—— 负责离线缓存，让断网的时候也能把 App 打开

## 数据存在哪？会不会丢？

存在**手机浏览器自己的储物柜里**，专业名字叫 `localStorage`。你不用去理解它怎么实现的，只要记住三件事：

1. 它只存在**这一个浏览器、这一台设备**上，换个手机、换个浏览器，数据不会跟过去
2. 如果你手动清了浏览器缓存/数据，这些单词也会跟着没
3. 现在这版还没做"导出备份"或者"多设备同步"，这是已知的短板，以后要补

## 代码是怎么组织的？（命名空间）

打开 `Grain.html` 找 `<script>` 标签，你会看到几乎所有代码都写在一个叫 `App` 的大对象里面，像这样：

```js
const App = {
  config: { ... },   // 写死的配置，比如存储用的 key 叫什么名字
  state:  { ... },   // 会变化的数据，比如现在有哪些单词、当前在哪个页面
  storage:{ ... },   // 负责存/取 localStorage
  render: { ... },   // 负责把数据画到屏幕上
  sheet:  { ... },   // 负责"添加/编辑单词"那个从底部弹出的表单
  utils:  { ... },   // 一些小工具，比如生成随机 id、防止 XSS 的转义函数
  init(){ ... }       // App 启动时第一个执行的函数
};
```

**为什么要这样写**：如果不这样，代码里到处都是散养的变量和函数（比如直接写 `let words = []`、`function save(){}`），项目做大了很容易出现"两个地方不小心用了同一个名字，互相覆盖，出了 bug 也不报错，你自己都不知道哪里出了问题"。套进 `App` 这一个对象里，就不会有这个问题，而且看名字就知道"这是负责存储的""这是负责画面的"，找代码更快。

**以后加新功能的规矩**：
- 如果是一个新的独立功能（比如以后要加"复习"），就在 `App` 下面新开一块，叫 `App.review = { ... }`，不要把代码硬塞进已经有的分组里
- 如果是给已有功能加点东西（比如给"添加单词"表单加个字段），就在对应的分组里加，比如 `App.sheet.save()` 里加一行
- 不要在 `<script>` 标签最外层直接写 `let xxx = ...` 或者 `function xxx(){}`，全部走 `App.xxx.yyy` 这条路径

## 每个单词存的是什么？

```js
{
  id: "w_1234567890_ab12cd",   // 自动生成的唯一编号，你不用管
  word: "abandon",              // 单词本身
  meaning: "放弃，抛弃",         // 中文释义
  example: "He abandoned the car.",   // 英文例句
  exampleZh: "他抛弃了那辆车。",       // 例句的中文翻译
  phonetic: "/əˈbændən/",       // 音标
  pos: "v.",                    // 词性
  tag: "",                      // 标签，你自己定义分类用的
  scene: "",                    // 场景（比如"面试"、"日常"）
  domain: "",                   // 领域（比如"商务"、"科技"）
  related: "",                  // 关联词，比如同义词/反义词
  status: 1,                    // 1 = 学习中，2 = 已掌握（手动标记，跟下面的间隔重复是两回事）
  date: "2026-09-10",           // 录入日期
  box: 0,                       // 间隔重复用的"盒子等级"，越高代表你记得越熟
  nextReview: 1757123456789,    // 下次该复习这个词的时间戳，复习功能会用到这个字段
  createdAt: 1757123456789      // 创建时间，列表按这个排序（新的在前面）
}
```

`box`/`nextReview` 这两个字段现在还用不上（复习功能没做），但是已经在"添加单词"的时候就写进去了——这样等复习功能一开始做，不用再回头给老数据"打补丁"，数据从一开始就是齐的。

## 以后加字段/加功能的注意事项

**如果要给单词加一个新字段**（比如以后想加"词根"）：老单词的数据里是没有这个字段的，直接用会报 `undefined`。做法是在 `App.storage.load()` 里加一段"迁移"代码——检查每个单词有没有这个字段，没有就给个默认值，然后存回去。这个手法已经在 Words.html 那个老项目上验证过一次了（给 209 条老数据补 `box`/`nextReview`），效果稳定，以后照着抄就行。

**每加一块新功能，记得写完就测一遍**——不用多复杂，能验证"加了新东西之后，原来能用的东西还能用"就够了。

## 现在做到哪一步了？

- ✅ 数据结构 + 本地存储
- ✅ 添加/编辑/删除单词（右下角 "+" 按钮，从底部弹出表单）
- ✅ 底部导航栏（词库 / 复习 两个 tab，图标是 📖 和 🔄）
- ✅ PWA 基础设施（manifest、离线缓存、内置图标）
- ✅ **复习功能**（间隔重复算法、今日复习/全部单词切换、翻卡交互）
- ✅ **备份/恢复**（右上角 ⚙ 按钮，JSON 导出 + 导入，导入时会先显示"新增/重复/跳过"数量，选"合并"还是"覆盖"）
- ✅ **云同步**（GitHub Gist，跟 Words.html 共用 Token、但各自独立的 Gist；改动后 8 秒自动推送，启动时自动拉取；推送前会检查云端有没有被其他设备改过，有冲突会弹提示条，不会静默覆盖）
- ⬜ CSV 导出（备份优先级更高、已经做完，CSV 只是"能被 Excel 打开"的便利格式，不急）
- ⬜ 批量操作

## 云同步怎么配置

1. GitHub 网页右上角头像 → Settings → Developer settings → Personal access tokens → 生成一个新 token，权限勾 `gist` 就够了（Words.html 那边如果还在用，同一个 token 可以直接复用）
2. 去 gist.github.com 新建一个空白 Gist（内容随便填，保存后就有了）——**注意不要跟 Words.html 用的是同一个 Gist**，复用同一个会导致两边互相误报"云端冲突"，这个在前面的讨论里踩过一次坑
3. 把这个 Gist 网址最后那串 ID 复制出来
4. App 里点右上角 ⚙ → 云同步，把 Token 和 Gist ID 填进去保存

配置完之后，改动会在停止编辑 8 秒后自动同步，不用每次手动点。

## 部署方式

跟之前 `vocab-pwa` 项目一模一样：新建一个干净的 GitHub 仓库，把 `Grain.html`、`manifest.json`、`sw.js` 这 3 个文件传到根目录（`README.md` 这份文档不影响运行，但建议一起传上去，方便以后翻）。传完 Settings → Pages 里开启，等生成网址后手机浏览器打开、添加到主屏幕。**不要传进 Words.html 正在用的那个仓库**——现在功能还没搬齐，传进去会把正在用的工具替换成半成品。

**注意**：主文件叫 `Grain.html` 不是 `index.html`，所以网址不是干净的 `你的用户名.github.io/repo/`，得完整打上文件名：`你的用户名.github.io/repo/Grain.html`。只有第一次部署时需要记这个完整网址——"添加到主屏幕"之后，图标记的就是这个完整地址，以后点图标直接打开，不用再手动输。
